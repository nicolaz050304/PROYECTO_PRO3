## ✅ LO QUE YA FUNCIONA (end-to-end: frontend -> REST -> MySQL en RDS AWS)
- LOGIN REAL: UsuarioRS/login valida correo+password contra la BD (texto plano), devuelve el usuario
  real (id + rol vía tipoUsuario: ADMINISTRADOR/ANFITRION/INVITADO), sin password. El frontend
  (AppState) guarda el usuario real; EsAdmin() mira el ROL (no el correo). Login.razor valida de verdad.
  Usuarios de prueba en docs/usuarios.txt (todos password demo1234).
- ALOJAMIENTO: lectura (Explorar, detalle, mapa Stadia con coords) + escritura (crear alojamiento).
- RESERVA: lectura (Mis Reservas con datos reales). [timeout frontend 20s; endpoint tarda ~8s]
- RESEÑA — MÓDULO COMPLETO:
  * Crear (modal en Mis Reservas, con validación 1-5 estrellas y >=10 chars).
  * Leer en el detalle del alojamiento.
  * Vista de ANFITRIÓN: página propia /mis-resenas (resumen estilo Airbnb + reseñas agrupadas por
    alojamiento, solo TipoAutor INVITADO). Accesible desde el menú "Como anfitrión".
  * Moderación ADMIN: /admin/moderar-resenas (ver todas incl. ocultas, ocultar=DELETE/activo=0,
    reactivar=PUT/activo=1). Muestra nombre del alojamiento. Solo accesible para admin. Afecta lo que
    ven los usuarios en el detalle. Backend: ResenaRS/todas y ResenaRS/{id}/reactivar.

## ⚙️ OPTIMIZACIÓN (al final, con todo listo)
- HASHING de contraseñas: hoy en texto plano (login plano funciona). El usuario maneja todo el código.
  Pasos: hashear en login+registro + convertir/resembrar las contraseñas ya existentes en la RDS.
  Hacerlo en 2 fases (ya está el login plano; agregar hash encima). PRIORIDAD del usuario: hacerlo pronto.
- HIKARI (pool de conexiones): DBManager.getConnection() abre conexión nueva cada vez -> el endpoint de
  Reserva abre ~13 por petición (~8s). Pool -> <1s. Toca SOLO el DBManager; los DAO no cambian; beneficia
  a todos. Con commit de respaldo.
- REDIS (caché, sugerido por el profe): DESPUÉS de Hikari. Cachear lookups de Reserva y listados.
  Infra aparte (Docker/WSL + Jedis/Lettuce). Orden: 1) Hikari, 2) Redis.
- Demo: "calentar" el servidor antes de presentar + timeout 20s.
- NO hacer (sobre-ingeniería): balanceador de carga, microservicios, colas, CQRS.
